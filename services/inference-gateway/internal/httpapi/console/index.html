04 / PROVIDER TELEMETRY

Reported token usage

UNTRUSTED SELF-REPORT

Aggregates reported by the model provider for internally consistent, complete responses. Missing or inconsistent reports are not zero tokens. This is not measured generation, per-project billing, or the separately enforced Redis output-cap budget.

These counters reset when the Go gateway restarts. The upstream can misreport token counts. Model names, prompts, outputs and user/project IDs are not included.

05 / PORTFOLIO V1.0

Explore the local platform

OPERATOR-GUIDED

Follow an end-to-end reviewer journey. The control-plane UIs run separately on port 8000, and the gateway console runs on port 8081. These are not a shared authenticated session. All links use fixed local addresses and send no credentials.

  1. 01

    Register and approve a model

    Use the separate operator-only model manager to inspect installed Ollama models, pin a digest, approve and load a revision. A configured local operator token is required.

    Open Model Manager ↗
  2. 02

    Invoke, observe, and roll back

    Run the approved model's single-turn playground on the control plane; inspect gateway admission, outcomes and provider-reported usage here. Use the model manager's deployment section for version changes and rollback.

    Review live inference metrics ↓
  3. 03

    Optional user identity workflow

    Explore OIDC sign-in, organizations and projects only if a real identity provider, PostgreSQL and Redis have been configured. This identity is separate from the local operator token.

    Open Account Console ↗

A dashboard visit alone does not prove a Mac/Ollama run, authenticated deployment, quality parity or an inference speedup. Portfolio v1.0 requires real operator evidence and controlled benchmarks.
